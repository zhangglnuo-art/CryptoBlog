[Layer 2](/blog/layer-2-explained) 把以太坊上贵的计算搬到外面做，所以转账便宜很多。名字却分成两派：一边是 Arbitrum、Optimism、Base，另一边是 zkSync、Starknet、Scroll 这些带 ZK 的链。

两边都叫汇总（Rollup），都把结果交回以太坊主网。差别在于主网**凭什么相信这些结果**。一个先假定没错，等人来挑错；一个当场交出一份数学证明。

## 汇总在做什么

以太坊主网贵，是因为每笔交易都要全网重复计算。汇总换了一个分工：

- 大量交易在 Layer 2 上执行、打包
- 打包后的数据和结果提交回以太坊
- 以太坊负责保管这些记录，并在规则满足时承认它们

你在 L2 上转账，付的是 L2 的费用，通常比主网 [Gas](/blog/gas-fee-explained) 低一个数量级以上。资产的安全预期，则取决于这些记录有没有真的回到以太坊、以及主网用什么方式确认它们没被改过。

## 乐观汇总：先通过，留一段时间给人挑错

**乐观汇总（Optimistic Rollup）** 的态度是：提交上来的结果先视为正确。

任何人都可以在一段**挑战期**里拿出证据，证明某笔结果是错的。这个证据叫欺诈证明。挑战成功，错误结果会被推翻，相关保证金会被罚。挑战期内没人提出有效异议，结果就在主网上定下来。

因此官方桥把资产从这类 L2 提回以太坊主网，通常要等挑战期结束。很多这条路线上的网络，这个等待大约是 **7 天**。它不是转账卡住了，而是协议在等「有没有人证明这批账是假的」。

Arbitrum、Optimism，以及基于 Optimism 技术栈的 Base，都属于这一类。日常在 L2 里面互相转账，不用等这 7 天。7 天出现在你走**官方桥撤回到主网**的时候。

这套安全有一个前提：挑战期内至少存在一个诚实、而且来得及出手的挑战者。如果错误结果没人挑战，主网会接受它。实际网络用保证金和奖励让挑战者有动机盯着，但「先假定正确」就是这个设计的核心。

## 零知识汇总：先交出证明，主网再认可

**零知识汇总（ZK Rollup）** 不靠别人来挑错。每批交易附带一份数学证明，证明这批状态变化是按规则算出来的。以太坊上的合约验证这份证明。证明通过，结果就被接受。

这里的「零知识」容易听偏。对用户来说，重点不是把交易内容藏起来——很多 ZK 汇总的转账仍然是公开的。重点是**用一份短证明代替把所有计算在主网上重做一遍**。

因为主网核验的是证明，而不是在等挑战期，官方桥提回主网可以短得多，常见是证明生成并提交之后的几分钟到几小时。证明本身要时间，所以也不是你一点击就在主网到账。

zkSync、Starknet、Scroll、Linea 常被归在这一类。它们的虚拟机、证明系统并不相同，体验和费用会有差别，不能因为都写着 ZK 就当成同一种产品。

## 一张表看完用起来的差别

| | 乐观汇总 | 零知识汇总 |
| --- | --- | --- |
| 主网凭什么相信 | 挑战期内没人证明它是错的 | 验证数学证明通过 |
| 官方桥提回主网 | 通常要等挑战期，常见约 7 天 | 等证明提交和验证，一般是分钟到小时 |
| 代表 | Arbitrum、Optimism、Base | zkSync、Starknet、Scroll、Linea |
| 多出来的信任点 | 挑战期内得有人真的去挑战 | 证明系统本身被正确实现 |
| L2 内部转账 | 不等挑战期 | 不等证明上主网 |

安全上没有「ZK 一定更稳、乐观一定落后」这种排序。两边都把数据交回以太坊时，都是在借用主网的结算。两边在实践中又都可能有排序器、升级钥匙和管理员：排序器宕机会让你暂时发不出交易，升级钥匙则意味着规则还能被一小群人改。看一条 L2，要看它有没有把数据交回以太坊、升级权在谁手里，而不只看它属于哪一派。

还有一种相近但更弱的设计：计算用了证明或挑战，数据却没有提交回以太坊，而是放在别的地方。它的手续费可以更低，主网却无法独自恢复全部记录。看到 ZK 或 Rollup 的字样时，先确认数据是不是在以太坊上。

## 等不及官方桥的那条路，是另一笔信任

很多人从 L2 回到主网，或者在 L2 之间移动资产，并不走官方桥。流动性桥和跨链兑换用别人已经放在目的地的资金先垫付，所以不用等 7 天。

你换来的速度，对应的是对那条通道的信任：垫付方、合约和报价。它解决的是等待，不是把乐观汇总变成零知识汇总。官方桥的挑战期还在，只是你没走那条出口。通道怎么选，见[跨链桥](/blog/what-is-cross-chain-bridge)和[跨链兑换](/blog/cross-chain-swap-guide)。

日常如果只是在一条 L2 里转账、兑换，两种汇总的等待差几乎感觉不到。差别变得具体，是在你要把大额撤回应以太坊主网、又坚持走官方桥的时候。

## 常见问题

**Q：我该选乐观汇总还是零知识汇总？**
先看你要用的应用在哪条链上，而不是先站队技术名词。两种都能显著降低手续费。只有在你经常要把大额从 L2 官方桥撤回应主网时，挑战期的长短才会变成使用上的差别。

**Q：Base 是哪一种？**
Base 使用 Optimism 的技术栈，属于乐观汇总。在 Base 里转账不用等 7 天；通过官方桥撤回应以太坊主网，才进入挑战期。

**Q：ZK 是不是代表交易更隐私？**
在这些扩容网络上，通常不是。零知识在这里主要用来压缩并证明计算是对的。转账记录在区块浏览器上仍然可以查。别把它理解成混币。

**Q：官方桥显示还要等几天，钱是不是丢了？**
在挑战期里，提款是排队确认，不是转丢。用交易哈希在对应的浏览器里能看到它停在哪一步。只有你走了别的桥、地址或链不对，才按[转错](/blog/crypto-transfer-mistakes)来处理。

**Q：排序器是一家公司，还算继承以太坊的安全吗？**
排序器负责替你排出交易顺序，很多 L2 目前仍是单一运营方。它停摆时，链会暂时不好用。只要数据已经提交到以太坊，并且退出机制还在，运营方不该能悄悄改掉已经交回去的账。停摆影响的是「现在能不能交易」，和「账能不能被偷偷改掉」不是同一件事。

## 小结

乐观汇总先承认结果，留出挑战期让人证明它是错的，所以官方桥提回主网常常要等大约 7 天。零知识汇总为每批交易附上数学证明，主网验证通过就承认，官方退出通常是分钟到小时。两边在链内转账都很快，也都还要单独看数据有没有交回以太坊、升级权在谁手里。等不及官方桥时可以走别的通道，那是在换一种信任，不是在取消原来的规则。
